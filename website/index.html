How it works

From request to reviewed diff, automatically.

Other tools give you parallel agents and leave the splitting, merging and checking to you. SwarmCode runs the whole loop.

  1. 1PlanA planner maps the code and splits the work into a dependency graph with clear file ownership.
  2. 2Build in parallelAgents work at the same time, each in its own isolated git worktree.
  3. 3MergeResults merge as they finish; an agent resolves any conflicts.
  4. 4TestYour test command runs; failures go back to the agents automatically.
  5. 5ReviewAn independent reviewer and a security gate check the combined change.
  6. 6ApplyYou get one diff and a proof report. Apply it, or keep it on a branch.

Features

Built to be trusted, not just fast.

Parallel agents that finish the job

Big tasks are planned, split and built by several agents at once, then merged, tested and reviewed. Small tasks go straight to a single agent. SwarmCode picks, and asks before spending more.

Hidden-test guarantee

Before any code is written, a separate agent turns your request into acceptance tests the builders never see. The work is done only when they pass.

Best of 3

Three independent attempts, even on different models. Each is graded on your tests and on security, and a judge picks the winner.

Proof for every change

A report with every check, the files changed, models, tokens and cost. One command turns it into a pull request.

Security gate

New secrets, injection risks or disabled TLS that a change introduces are caught and fixed before you see it.

Any model, your keys

Claude, GPT, Gemini, DeepSeek, OpenRouter or free local models. A strong model plans while fast ones build.

Long sessions without amnesia

Every agent keeps a searchable journal, so it can recall file contents and decisions even after its context is compacted. Huge logs are kept out of context and read on demand, which cuts token use.

Time travel

Every request is checkpointed. Replay what happened, or re-run any request from its exact starting code with another model.

Health radar

One scan for secrets, risky code, vulnerable dependencies, failing tests and hotspots, each with a one-click fix.

Browser, PDFs and documents

Agents test your web app in a real browser, read PDFs and Word files, and produce polished PDF reports.

What it costs: a typical medium task used about 241k tokens in agent mode. That is roughly $0.56 at Sonnet-class API prices before prompt caching (caching lowers it), and $0 with local models through Ollama. Swarm and best-of-3 modes use more; SwarmCode shows the estimate and asks before using them.

Model for every tool: gpt-oss:120b via Ollama Cloud. Run on October 15, 2026. One run per task and tool, same model for every tool, graded by hidden acceptance tests the agents never saw. Single runs vary, so treat small differences as noise. Token counts are shown where a tool reports them; opencode does not.

These results are from SwarmCode 1.0.0. Since then, agents trim old tool output from their context: re-running the two most token-heavy tasks in agent mode used 590k–879k tokens instead of 2.18M (8 utility functions) and 125k–234k instead of 313k (4 data structures), with the same pass results. A full re-run with several runs per task is next.

How it works: each task starts from a fresh copy of a small real-world project. When an agent finishes, hidden tests are copied in and run; pass means every requirement works. The harness is open source, so you can run it on your own models: npm run bench -- --external "name=your-cli {prompt}".

Privacy

Your code stays yours.

  • Runs on your machine. Code goes only to the model provider you choose, or nowhere with local models.
  • API keys are encrypted with your OS keychain.
  • No telemetry.
  • Every edit and command needs your approval, unless you turn on autonomous mode.
  • A full audit trail of what every agent did.

FAQ

Questions

Is it free?

Yes. SwarmCode is open source (Apache-2.0). You pay your model provider for usage, or use free and local models through Ollama.

Which models work best?

Any capable tool-calling model works. A strong model (such as Claude Opus or GPT-class) for planning and review, with a faster one for the parallel workers, gives the best balance of quality and cost.

Do I need git?

For parallel agents and best-of-3, yes: each agent works in its own git worktree. The single agent works in any folder.

Windows says the app is unrecognized.

Early builds are not code-signed yet. Click "More info", then "Run anyway". Signed builds are on the way.

macOS and Linux?

The CLI runs everywhere (npm i -g swarmcode). Desktop builds for macOS and Linux come from the same code and are coming soon.

Can my team share skills?

Yes. Turn a good session into a skill with one command, and share it with SHA-256 pinning and Ed25519 signatures so nobody can tamper with it.
